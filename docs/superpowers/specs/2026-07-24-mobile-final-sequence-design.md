# 移动端最终页顺序展示设计

## 目标

修复移动端到达 10:50 后，承诺卡覆盖“这一次，我们把早晨好好说完。”主叙事的问题。最终页应先完成情绪收尾，再让用户继续阅读承诺内容。

## 已确认交互

- 仅调整宽度不超过 700px 的移动端布局；桌面端保持当前左右并列结构。
- 到达 10:50 时，第一屏完整显示：
  - `10:50 / 如果这一次，我做对了`
  - `这一次，我们把早晨好好说完。`
  - 对话、过程描述和反思文字
- 主叙事底部显示轻量提示“向上滑，看看我会怎么做”。
- 用户在中间内容区域向上滑后，承诺卡作为下一段内容出现，并使用短距离上移加淡入，不覆盖主叙事。
- 底部时间轴继续固定在页面底部，不参与中间内容滚动。
- 右上角视频窗继续固定在原位置，可正常切换双方视角。
- 到达最终节点时不自动跳到承诺卡，避免错过主叙事。

## 布局方案

移动端 `.commute-body` 在 `has-arrived` 状态下成为独立的纵向滚动容器。`StageNarrative` 和 `present-closing` 从重叠的绝对定位关系改为容器内的上下两段：

1. `StageNarrative` 至少占满中间可视区域。
2. `present-closing` 恢复正常文档流，位于主叙事之后。
3. 两段使用纵向滚动吸附作为辅助，但不强制跳页。
4. 时间轴仍由页面外层网格的最后一行承载，因此不会跟随内容滚动。

## 动效与可访问性

- 承诺卡进入视口时使用现有 Motion 淡入动效，位移保持克制。
- `prefers-reduced-motion` 开启时取消位移动画，只保留即时展示。
- 滑动提示为可读文本，不使用只存在于 CSS 伪元素中的内容。
- 主叙事和承诺卡都保持正常 DOM 顺序，读屏顺序与视觉顺序一致。

## 测试与验收

- 组件测试：到达 10:50 后，主叙事、滑动提示和五条承诺同时存在，且顺序正确。
- CSS 回归测试：移动端最终态使用滚动容器，承诺卡不再绝对定位。
- 浏览器验证：400×897 下首次到达时完整看见主标题；向上滑可看见承诺卡；时间轴和视频窗不移动、不遮挡。
- 横屏回归：667×375 下承诺卡仍可滚动阅读，并与时间轴保持间隔。
- 全量测试和 GitHub Pages base path 构建通过后再发布。
